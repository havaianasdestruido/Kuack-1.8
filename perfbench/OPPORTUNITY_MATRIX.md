# LUT / conversion opportunity matrix (deliverable C)

Ranked by **measured CPU impact**, not ease of implementation. Ranks 2–3 are isolated PoCs, not shipped
production changes; ranks marked **Reject** are retained because they were measured and rejected, as
the spec requires.

**Frequency legend:** `M` = measured in a deterministic benchmark workload; `E` = source-level
estimate from call-site/loop structure, **not** a full-game profile. No FPS/frame-time distribution
was captured.
**Distribution legend:** `D` = deterministic sequential bytes/angles + fixed LCG random + adversarial
negative/out-of-range inputs. No real game input trace was available.
**Runtime legend:** `JVM` = HotSpot 17/25 with ECJ-compiled real classes; `V8` = real TeaVM 0.9.2 JS
running in Node/V8, **not Chromium**; `WASM`/`native` = isolated PoCs.

### Ranking notes

- Ranks **1, 4, 5, 7, 8, 9** are shipped production improvements verified across **HotSpot JDK 17**, **HotSpot JDK 25**, and **TeaVM 0.9.2 / V8 12.4**.
- Ranks **2–3** are isolated WASM and C native PoCs; Rank **6** is the pre-existing HEAD `Matrix4f.rotate` optimization regression-guarded by the suite.
- Ranks **10–14** are measured rejections kept for transparency so hypotheses and verified improvements stay clearly separated.
- "Measured impact" is isolated CPU time. **No rank implies a full-game FPS change.**
